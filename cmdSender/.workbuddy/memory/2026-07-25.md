# 2026-07-25 工作日志

## cmdSender 完整重写

### 原始问题
1. Scheduler.ResetQueue 从已耗尽队列重建 → 第一轮后命令全部丢失
2. WindowFromPoint 仅返回顶层窗口, 无法获取子控件句柄
3. 窗口拖动 MouseUp 时 e.Location 不准确(鼠标离开按钮后坐标错误)
4. 文件保存总是弹对话框, 未跟踪文件路径
5. 循环发送使用全部行, 不支持选中多行
6. UI 绝对定位重叠, 无自适应缩放

### 修复方案
- **CommandSender.cs**: 递归 ChildWindowFromPointEx 获取最深层子窗口; 新增 PostMessage(WM_CHAR) 和 SendKeys 两种发送方式; ForceSetForegroundWindow 用 AttachThreadInput 绕过前台限制
- **Scheduler.cs**: async/await + CancellationToken 替代双 Timer; generation 机制确保只有最新任务的 OnCompleted 触发; 发送前检查 IsWindowValid
- **MainForm.Designer.cs**: Dock 布局(panelTop/Top + panelRight/Right + richTextBox/Fill + statusStrip/Bottom); GroupBox 分组控件; ToolTip 提示
- **MainForm.cs**: Capture 机制 + Cursor.Position 实现精准拖动; 选中行/全部行循环发送; 文件路径跟踪 + 脏标记; 窗体关闭时保存提示
- **cmdSender.csproj**: 转为 SDK-style 以支持 dotnet build

### 编译
- `dotnet build` 通过, 0 警告 0 错误
- 输出: bin/Debug/cmdSender.exe (30720 bytes)

## 2026-07-25 晚间修复与优化

### 问题1：发送需二次点击目标窗口
- **根因**: 默认后台发送(PostMessage WM_CHAR)对记事本等 Edit/RichEdit 控件无效——无焦点时消息滞留队列，窗口获焦后才处理
- **修复**: 默认发送方式改为前台 SendKeys(SelectedIndex=1)，点击即达
- **增强**: PostMessage 方式在发送字符前先 SendMessage(WM_SETFOCUS,0,0)，提升后台发送兼容性

### 问题2：应用程序图标 + UI 优化
